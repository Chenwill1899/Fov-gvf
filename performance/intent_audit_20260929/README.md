# 摇杆改向与水流参考线检查（2026-09-29）

本次为诊断，未修改控制源码/运行配置，未启动 Isaac、ROS 或实际手柄。

## 结论

- 运行入口启用 paper_enabled；新意图通过 human_intent 传入核心。
- 目标每次构场按当前意图的三维夹角选择；旧目标只在等价最优时用于平局选择。明显改向会立即触发构场（不等常规0.10秒），丢弃旧源/目标提示、禁止旧参考延续并从当前可用角状态初始化。
- command_change_angle=0.05rad，约2.865度。判定相对 previous_intent_，该变量在每次成功构场后更新，而非只在主动改向重设时更新。因此缓慢且持续改变意图可能始终被判为未改变并继续旧参考。
- 独立调用现有 paper_guidance.cpp/depth_angular_core.cpp 验证：初始化后每0.12秒增加1度，直到20度；20次均 refreshed=1、continued=1、reset为空。下一步20→35度触发COMMAND_CHANGE且continued=0。
- 同一空旷夹具内，前20步goal_deg与cmd_deg都正确跟随0→20度，状态TARGET_HOLD。因此此结果确认“慢改向漏重设”，不能将其表述为“水流不更新”或“该缺陷必然造成偏航”。突然35度步骤进入TRACKING，单步输出约18.639度；本次未将该单步表现外推为收敛结论。
- 运行节点速度>0.03m/s时用实测速向作为虚拟角域中心；明显侧向/反向意图可能位于当前90度水平角域之外，只能先影响域内最接近的可行目标。该约束与转向速率、动力学及安全检查共同限制响应，不能把所有延迟视作旧参考未清除。
- paper_guidance_check覆盖一次明显改向重设，未覆盖缓慢累计改向；paper_closed_loop_check的command_change用例检查非零位移/接受次数，但没有改向后Y方向跟踪误差或收敛时间断言。此前“改向恢复通过”不能解释为“意图跟随响应完整验收通过”。
