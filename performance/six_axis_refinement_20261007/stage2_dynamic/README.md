# EGO1P5 第二轮②动态障碍关联优化

本阶段比较的是已实现动态预测的原版P5与本轮优化后的P5，双方均启用相同的动态轨迹模型；不是“关闭动态”对“开启动态”。原版源码来自本轮 `../baseline/sources.tar.gz`，未使用P3/P4运行结果。

## 方案和实现

原关联对每个当前0.3m障碍格扫描全部历史轨迹。新版先筛选同view且dt在[.025,.4]的可关联预测位置，按位置跨度最大的世界轴排序；仅查询当前格该轴±.75m（另加只向外扩的舍入保护）内的候选。三维距离表达式、.75m门限、原索引平局、贪心一对一、3m/s速度上限、.35/3m/s误差、.5m/s²加速度界、.5s TTL以及全部未匹配轨迹保留策略保持。≤64条历史轨迹走原扫描，避免小场景索引成本。

同时对运动证书的NaN/负半径/负时间范围/非法轨迹失效关闭；原生点变换后非有限或超出100km坐标范围时失效关闭，避免整型体素索引溢出。没有删除障碍或缩减保护余量。

变更文件：`src/pc_gvf/src/dynamic_obstacles.cpp`、`src/pc_gvf/test/cpp/dynamic_obstacles_check.cpp`。

## 同输入消融

固定16/64/256/900点，160帧，2路交错view；相机持续平移、正弦转动，障碍小幅运动，保持在相机前方。每组重复5次。独立编译原版与新版，编译参数完全相同（`-O3 -DNDEBUG -std=c++14`），调用真实生产模块；CPU计时只包含`ingest`。

| 每帧输入点数 | 原版160帧CPU均值ms | 新版ms | 比值 |
|---:|---:|---:|---:|
| 16 | .2110 | .1850 | 1.14× |
| 64 | 1.3606 | .9616 | 1.41× |
| 256 | 18.2286 | 5.6498 | 3.23× |
| 900 | 253.1178 | 41.2484 | 6.14× |

20对试验的轨迹顺序、位置、速度、stamp、radius、view、observations与overloaded的64位滚动哈希全部相等，38400次运动查询的决定哈希全部相等。非法数值负例错误放行4→0。动态平局原索引选择、超大坐标拒绝独立回归通过。

原始证据：`baseline.csv`、`optimized.csv`、对应stderr；机器汇总`summary.json`；最终源哈希`source_sha256.json`；纯模块边界验证`safety_regression.cpp`与`safety_regression.log`。主CTest由root统一构建执行，结果另列，本文不提前认定通过。

## 探索与限制

第一轮相机单调转至障碍后方，导致16/64/256点试验后半段逐步无点，且16点索引准备出现极小绝对开销退化（.1232→.1756ms/160帧）。全部初始源和数据保留在`exploratory_rotating/`。据此增加小场景原扫描路径，并将正式输入改成持续可见正弦转动；没有删除初轮结果。

本结果只说明动态关联计算更快、同输入跟踪/安全输出保持及非法数据拒绝更强；计时不含段证明查询、完整控制器、ROS、Isaac或实飞。新增段证明有限数校验的完整整机开销未在此量化。CPU未绑核，主机并非专用隔离测试机，尤其亚毫秒小场景计时只能视为此次样本。不能据此宣称动态环境整体导航已更快。

## 复现

将基线tar解压到独立临时目录，使用以下相同编译/执行命令，分别把`SOURCE`指定为解压根目录与当前EGO1P5根目录；两者都调用本目录同一个`refinement_probe.cpp`。保存输出到新的独立目录，不覆盖本次结果。

```bash
c++ -O3 -DNDEBUG -std=c++14 -I/usr/include/eigen3 -I"$SOURCE/src/pc_gvf/include" \
  refinement_probe.cpp "$SOURCE/src/pc_gvf/src/depth_angular_core.cpp" \
  "$SOURCE/src/pc_gvf/src/dynamic_obstacles.cpp" -o /tmp/dynamic_probe
/tmp/dynamic_probe
```
