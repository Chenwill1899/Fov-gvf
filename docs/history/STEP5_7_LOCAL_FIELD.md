# 第五至第七步：尺寸约束、局部场输入与期望方向

2026-11-03 17:58 +0800：C++模块已接入接收/2ms读取流水线，4包构建、CTest6/6、ASan/UBSan与六份真实存档独立复核通过。当前完成场构造输入和查询接口，尚未实现粗细调和场、梯度曲线积分、整条最终空间曲线包络检查或运动输出。**本版未运行新Isaac/FIFO仿真**；此前0/15020读取间隔>2.2ms属于[上一版冻结ELF](DEPTH_PARALLEL_REPAIR.md)，不直接继承为新版本成绩。

## 固定参数和处理位置

| 参数 | 当前值 | 含义 |
|---|---:|---|
| 机体球形包络半径r | 0.10m | 单个待查询中心的尺寸约束 |
| 局部观测范围Lp | 3m | 以深度采集时机体原点为球心 |
| 读取/控制周期 | 2ms现实时间 | FIFO10＋200μs方案保持；本版尚未在线复测 |
| 期望速度 | 0～10m/s | 输入目标值，不是执行器指令 |
| 参考加速度上限 | 20m/s² | 固定周期速度向量增量≤0.04m/s |

新同步组仍在四路常驻SCHED_OTHER工作线程CPU1～4中执行“补值→块/双图摘要→原方向索引→局部来源核对”；接收线程先归并原索引，再归并局部数据，完成后才发布同一保护槽。读取线程CPU5直接复用，重复组不重算。无新增工作线程、逐像素锁或稳态内存申请。

D与D_filled保持；新增原始D的16×16最小值/有限正数计数摘要，与已有补值图摘要分别保存。块均值扫描同时生成两图的精确最小值和原始可用数，跨摘要边界和小边缘块按原尺寸处理，没有用块均值替代区域最小值，也不创建逐像素V/U掩码。

## 第五步：球体投影和全分辨率查询

`LocalGeometryTables`初始化时固定K、R_CB、-R_CB t_BC、投影行范数和r²等参数，之后复用。对待查询中心c_B，计算c_C=R_CB c_B-R_CB t_BC。若相机坐标Z_c≤r，或包络越过近裁面/图像边缘，则该相机不能给出完整通过依据。

对零偏斜K，球的水平投影边界为：

```text
u± = fx * (Xc*Zc ± r*sqrt(Xc²+Zc²-r²))/(Zc²-r²) + cx
```

垂直方向相同；实现支持K的图像轴偏斜项。使用球切线投影边界，而非仅fx*r/Z的近似。边界向外取整为图像半开矩形，显式保留是否完全在图内；越界区域只查询可见交集，不能凭交集认定完整球体可通过。

`LocalFieldView::sphere(c_B)`对各相机分别调用全分辨率`region`：

- `PotentialObstacle`：投影区域已有补值图深度≤Z_c+r，作为保守尺寸约束；矩形、遮挡或补值可能造成保守拒绝，不宣称是精确几何碰撞。
- `ObservedClear`：至少一路完整包络投影在图内且位于已读回的近裁面之后，区域**全部原始像素**有限正数，原始最小Z严格大于Z_c+r，同时没有其它相机给出上述潜在障碍约束。
- `Unknown`：深度缺失、只靠补值、近裁面未知、盲区或视野不足，没有足够通过依据。各相机分别检验自己的光轴Z，不跨相机比较Z选最近。

通过依据对应离散深度图的保守矩形覆盖；没有把同一方向整条射线或整个1°格标为自由。原始孔洞即使已补成有限正数，也不能自动获得通过依据。

相机实际偏置约0.22m。当前没有明确仿真初始净空证明，因此机体与相机之间的近场盲区保留未知。可选`SimulationInitialClearance`接口仅接受调用方已经验证的、带proof_id、精确输入时间戳/序号和机体系初始净空球半径的依据；不能把静止、无碰撞消息或零速度当证明，不自动继承到后续组。当前默认不提供该依据。

`c_B≈0`直接返回`CurrentPositionNotEvaluated`，不单独重复检查当前位置；中心超过3m返回`OutsideLocalRange`。该接口检查单个包络中心，本步不生成轨迹、不遍历检查整条曲线。

## 第六步：平移外参下的3m阈值和方向来源

启动时复用已生成的块中心q=R_BC*b；原图像素另外预计算对应q与Z_limit，用于边缘核对。均不保存表面三维点。令：

```text
A = q·q
B = q·t_BC
C = t_BC·t_BC - Lp²
Z_limit = (-B + sqrt(B²-A*C))/A
```

这是`||Z*q+t_BC||=3m`的正出口，包含相机位置，不能直接用Z≤3m。实现用数值稳定的等价分支。当前相机原点在局部球内，因此`0<Z≤Z_limit`对应所需范围；若配置把相机原点移到球外，拒绝这一单阈值模型，不错误套用。

3×3补值均值先与块中心阈值粗筛；同时用块内**全分辨率最小深度**与像素阈值上界保留边缘候选，即使块均值很远也不漏掉近像素。候选块逐原像素检验有效Z与自己的Z_limit，用预计算q做Z*q+t，只临时计算方向；局部障碍记录相机/原像素/Z/原始或补值来源/同组身份。对应1°×1°网格保存CSR来源，不按跨相机Z取近。

原始深度超过3m阈值仍保留局部射线依据：每块保存原图范围、原始可用/总像素数，以及相机光轴区间`[near_clip_Z, min(raw_min_Z, block_min_Z_limit))`。原始最小值和阈值均用原分辨率核对，3m处没有虚构障碍面。

自由射线束关联到其局部截断端点的机体系方向格，仅作为来源索引；相机平移时，途中机体系方向可能改变，**不能把这一格整条机体系径向段判成自由**。区域缺原始像素或缺近裁面时，记录条件/不完整依据，查询仍需全分辨率包络核对。小于表面Z的开区间才是射线证据，不包含障碍表面自身。

每格同时提供障碍来源、射线束来源、无证据标记及观测/不完整边界；方位角首尾相邻，俯仰边界不跨极点盲补。`uncertain_coverage=false`仅表示这些来源没有已知缺口，不代表整格完整覆盖。未观测部分始终未知；没有创建自由域导航策略、点云、环境地图或整张方向最大直行距离图。

## 第七步：统一期望输入

`DesiredInput`和`desired_motion`全部在C++中；位姿状态现包含p_W、v_B和R_WB。

| 来源 | 入口 | h_B | 速度语义 |
|---|---|---|---|
| 机体系手柄速度 | `/human_intent` TwistStamped，frame_id=`base_link` | u_B | 模长限幅到0～10m/s |
| 既有世界系手柄速度 | 同话题，frame_id=`world` | R_WB^T*u_W | 保持既有速度消息单位 |
| 世界系目标点 | `/controller/goal` PointStamped，frame_id=`world` | R_WB^T*(g_W-p_W) | `--goal-speed-mps`，默认10，范围0～10 |

启动参数`--desired-source velocity|goal|none`明确选择来源，默认velocity，避免手柄/目标互相覆盖；没有输入时输出零期望速度。手柄消息按m/s速度向量解释，若上游仅给单位方向，需上游赋予速度幅值，不暗中拉满10m/s。输入模长≤1e-9时不归一化，d_desired为零、v_desired=0；非有限输入返回valid=false和零速度。

`d_desired=h_B/||h_B||`与`v_desired`供后续粗细调和场使用。输入目标变化可立即把v_desired置零；参考曲线的减速另由20m/s²约束处理，不把有惯性的参考速度冒充零期望值。

`acceleration_limited_reference(previous,target)`为后续梯度积分提供固定坐标系速度向量限幅：目标模长≤10m/s，每2ms变化≤0.04m/s。它尚未接入未实现的调和场曲线，不代表现有Isaac执行器已实现20m/s²响应，也没有改平台旧执行参数。深度局部坐标属于该同步组采集时的机体系，期望方向使用当前位姿；后续移动控制需要按时间戳对齐或拒绝陈旧证据。本步不执行时间补偿。输入新鲜度/失联策略、梯度曲线积分和最终空间包络验收留在后续控制器中实现。
